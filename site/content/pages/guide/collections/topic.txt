  body: |
    A **collection** is a folder of items in `site/content/collections/`.
    Items look like pages (front matter + body) but have no URL; templates
    pull them in.

    ```
    site/content/collections/
      people/
        _collection.yaml     ← label, fields, admin tab, computed title
        ada-novak/
          item.txt
          photo.jpg          ← the item's files
    ```

    ```yaml
    # _collection.yaml
    label: People
    title:
      from: "{name} {surname}"   # computed title (≥ 0.10)
      input: readonly
    fields:
      name:    { type: text, label: First name }
      surname: { type: text, label: Surname }
      role:    { type: text, label: Role }
      photo:   { type: image, label: Photo }
    ```

    ## In templates

    ```twig
    {% for p in collection('people') %}      {# live items, by Sort then title #}
      {{ p.title }} — {{ p.extra.role }}
      {{ render_collection_item(p) }}        {# the body as HTML #}
    {% endfor %}

    {% set cta = collection_item('shared-blocks', 'intro-cta') %}
    ```

    Item files are served from `/media/_collections/<name>/<slug>/<file>`.

    ## The collections of this site

    | Collection | Used by | Shows |
    |---|---|---|
    | `banners` | the bar at the top, `layout.twig` | `color` fields; a draft and a scheduled item |
    | `people` | [Studio](/studio), the `person` block | computed title, `image` field |
    | `categories` | product *Category* select | a collection in the same admin tab as pages |
    | `shared-blocks` | [Studio](/studio), the `shared` block | items whose body is blocks |

    Items have `Status`, `PublishAt` and `ExpireAt` like pages — the top bar
    shows two banners because the third is a draft.

    ## Titles built from fields

    An item's title doesn't have to be typed: the collection can **build it
    from the item's fields** *(station0 ≥ 0.10)*. The `people` collection
    does — open [Ada Novak](/admin/collections/people/ada-novak/edit) in the
    admin: the *Title* input is greyed out and fills itself in as you type
    the first name and surname.

    ```yaml
    # _collection.yaml
    title: "{name} {surname}"            # short form = input: readonly

    title:                               # long form
      from: "{brand} – {model} ({year})"
      input: editable                    # readonly | editable | hidden
    ```

    | `input` | The editor sees |
    |---|---|
    | `readonly` (default) | the title, filled in live, can't be changed |
    | `editable` | the title fills itself in until the editor types their own; clearing it (or *Use built title*) makes it follow the fields again |
    | `hidden` | no title input, just a line with the result |

    - Placeholders are the collection's fields, plus `{slug}` and `{collection}`.
      Text between them is kept.
    - When a field is empty, the separator next to it is dropped:
      `{brand} – {model}` with no model gives just the brand, and an empty
      `({year})` disappears.
    - A select gives its stored value (the slug), an image its file name.
    - The result is **saved** into `Title:` like a typed title, so
      `item.title`, lists, slugs and imports by tasks all work as usual. A new
      item gets its slug from it.
    - After adding or changing the pattern, existing items update on their
      next save, or all at once:
      `php vendor/bin/console collections:retitle people --dry-run`, then
      without `--dry-run`.

- type: text
  body: |
    > **Collections only**
    >
    > Titles built from fields are a collection feature. **Pages** always have
    > a typed `Title:` — a page template's manifest has no `title:` pattern.
    > For a product page you can still *show* a composed heading in the
    > template, e.g. `{{ fields.brand }} {{ fields.model }}`, while the stored
    > title stays what the editor typed.
